# Owner-gated local orchestration

The runner is a local control plane, not a GitHub Actions agent and not a security sandbox. It uses the user's existing local CLI logins, creates one worktree per writer, stores durable state in ignored `.nyan-runner/state.sqlite3`, and gives GitHub Actions no Codex, Antigravity, supplier, payment, or production credential.

## Commands

From the repository worktree containing the runner:

```text
python scripts/agent_runner.py start --task ops/agent_tasks/NSB-041.json
python scripts/agent_runner.py status --run-id <run-id>
python scripts/agent_runner.py watch --run-id <run-id>
python scripts/agent_runner.py watch --all --role worker
python scripts/agent_runner.py watch --run-id <run-id> --after-cursor <cursor>
python scripts/agent_runner.py pause --run-id <run-id>
python scripts/agent_runner.py resume --run-id <run-id>
python scripts/agent_runner.py stop --run-id <run-id>
```

`start` launches a detached local runner process unless `--foreground` is supplied. `status` reports controller and registered-launcher PIDs/liveness, exact phase/HEAD, worker and reviewer session IDs, PR/CI URLs, counters, errors, and recent events. `watch` is a Windows-terminal-friendly, read-only viewer. It shows task/issue/run, role, worktree, branch, commit, session when available, real tool/file/command activity, phase/CI/review/fix/block events, and the last event time. It distinguishes process liveness from new activity and never invents a progress percentage or token count. `Ctrl+C` closes only the viewer; use `--after-cursor` to reopen without replaying already-seen records, `--once` for a snapshot, `--all` for the team, and `--role worker|reviewer|runner` to filter. Pause takes effect immediately during CI backoff and at the next safe checkpoint during a bounded model turn. Stop terminates the registered containment boundary before the claim can be released. Resume uses the same durable run, claim, worktree, branch, worker session, and existing PR.

The model/launcher keeps writing stdout and stderr directly to separate ignored raw protocol files. Independent tailers read those files while the process is alive and submit only to a bounded, non-blocking queue, so a slow or closed viewer cannot backpressure, duplicate, resume, terminate, or change the worker outcome. SQLite is the canonical redacted replay log: every normalized event has a deterministic invocation/channel/line key, and post-exit or crash recovery catches it up idempotently from the raw files. A dropped/error count marks live delivery as degraded while catch-up restores replay completeness. Persisted commands contain only an allowlisted executable/subcommand summary plus a digest; free-form agent text, command arguments, stderr content, tool error text, and aggregate output remain in ignored private protocol files and are never rendered by `watch`.

## Trust and review flow

Only committed, unmodified JSON files under `ops/agent_tasks/` are executable task inputs. A new run requires the file to match the exact resolved base SHA, then stores a canonical JSON snapshot and SHA-256 digest; later phases never reload mutable policy from the checkout. The runner reads a GitHub issue only to verify its number, URL, title marker, state, and labels; issue/comment/PR prose is never appended to a worker prompt.

For each run the coordinator resolves and persists an exact base SHA and absolute deadline, creates a distinct `nyan/*` worktree, and records an active SQLite claim before launch. A transactional process lease prevents concurrent controllers for one run. The launcher has its own absolute deadline and cannot run indefinitely after controller failure. Before the model command can start, the runner captures the launcher's OS creation identity and persists a random nonce plus an acknowledgement path. On Windows, an out-of-Job watchdog owns a named `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` Job, terminates it, and waits for `ActiveProcesses == 0`. On Linux, an in-group watchdog anchors the process-group ID until an out-of-group cleanup helper kills that group and proves it disappeared. Only the matching nonce acknowledgement permits the active record or claim to clear. PID reuse, missing identity, unreadable identity, missing acknowledgement, and nonce mismatch all fail closed. Once an interrupted invocation exits safely, recovery reuses the explicit CLI session recorded in its event stream. The viewer bypasses `RunnerService` and opens the existing database through SQLite `mode=ro`; viewing cannot create/migrate state or acquire a claim.

Worker output must include the GitHub issue number, branch, exact pre-commit HEAD, exact changed files, tests, result, and blockers. The worker edits only its worktree and cannot stage, commit, or push. UI task specs are rejected before launch unless they map Antigravity to the UI role, pin a discovered model, and grant exactly one literal `admin/src/features/<slug>/**` root. The frozen base must also contain clean, tracked root/Antigravity rules, the single-writer hook with distinct expected markers, and both project-local Impeccable provider trees. The Impeccable preflight requires the exact npm provenance, exact provider-specific front matter, a complete regular-blob inventory, and matching SHA-256 values for every instruction and executable in the committed payload; suffix, comment, duplicate, missing, extra, dirty, or relocked-to-another-source variants fail closed. On the first turn `--new-project` makes `agy` 1.2.7 hydrate those workspace customizations; `/impeccable polish` is the first prompt directive and fixes resume the same conversation. The runner authenticates exact hook-policy and Node-handler digests from committed `HEAD`; the hook blocks shell, background-task, scheduling, permission-escalation, and collaboration paths, and makes its own hook/rules/handler plus local command shims immutable before execution. The runner independently checks the clean parent SHA, all tracked/untracked/staged paths using NUL-delimited Git output, symlink/junction/reparse containment, nested policy/config denylist, the frozen allowlist, the fixed role ceiling, and the result schema; it stages exactly those paths, creates the commit, and only then pushes or opens/reuses a PR. The hook protects the execution guard, while the exact task path remains a post-write frozen-diff gate rather than a claimed sandbox boundary. The expected parent is persisted before launch; after a crash the runner applies the same Antigravity cwd/model/schema/usage/subagent validation and validates a durable result plus the single runner-authored commit before advancing, so it does not repeat the worker turn or create a second commit. This preserves worktree isolation without granting a model write access to the repository's shared `.git` directory.

CI polling uses bounded exponential backoff and no model call. A required check is accepted only from the newest workflow run whose `headSha` equals the current worker HEAD; an older failed attempt cannot override a newer rerun in progress. A failed required gate records exact-SHA run metadata, failed job names, and a deduplicated, secret-redacted, bounded check-run annotation excerpt, then rechecks owner control and the newest exact-SHA run before resuming the same saved writer session inside the shared three-round fix ceiling. The diagnostic JSON is explicitly untrusted and cannot expand the frozen path grant. Annotation retrieval is best-effort, so unavailable diagnostics do not prevent the fail-closed gate or bounded repair loop. Legacy runs that stopped at this exact CI checkpoint may be reclaimed only when their worktree is clean, HEAD/PR/session evidence is intact, and no competing claim exists. The independent Codex reviewer runs with the worktree read-only and only an isolated per-run temporary directory writable, then the runner verifies that the worktree stayed clean. It must return `PASS`, `CHANGES_REQUESTED`, or `BLOCKED` for that same SHA; nullable finding locations are still required schema fields. Findings resume the explicit saved writer session. A fix commit invalidates prior CI/review. Durable terminal event streams recover worker/reviewer session IDs and account usage exactly once before advancing, so a controller crash cannot erase tokens or duplicate a completed review. An owner pause uses the same registered OS containment boundary as stop but keeps the run nonterminal; recovery validates the partial protocol prefix, reuses the explicit writer session, and preserves only contained in-scope partial edits. Three fix rounds, five agent invocations by default, a persisted absolute deadline, and reported tokens are hard ceilings. Every individual Agent, Git, and GitHub subprocess recomputes a finite timeout capped by the remaining persisted deadline.

## Merge gate

Automatic merge and automatic next-task execution before its dependencies are merged are **BLOCKED**, including for otherwise low-risk PRs. GitHub's supported `--match-head-commit` precondition binds the reviewed head SHA but does not atomically bind the reviewed base branch. A base-retarget race therefore remains between validation and queueing. The service, policy, GitHub adapter, legacy authorization path, and repository mutation command all fail closed; an old local authorization file or the previously drafted confirmation sentence grants no authority.

Every reviewer PASS ends at `READY_FOR_OWNER`. The owner may merge through the protected GitHub UI. Once that exact reviewed merge is reconciled, the Codex coordinator may select and start the next committed dependency-ready task within the already approved scope; Nyan does not need to copy findings or assign routine work. A subsequent explicit `resume` only reconciles a PR already merged with the exact reviewed head and trusted base; it does not issue a merge. For `main`, completion then requires both `ci-gate` and the GHCR publish job for that merge commit. The runner never approves or merges its own runner/policy PR. A future unattended merge design needs a mechanism that atomically binds both head and base, or a new explicit product/risk decision; no current one-time permission is sufficient.

## Safety defaults and limitations

Every worker process receives `SUPPLIER_MODE=mock`, `PAYMENT_MODE=disabled`, and `ALLOW_REAL_PURCHASES=false`. Its environment is rebuilt from a small operating-system/path allowlist, not a secret-name blacklist; database access is forced to a dedicated fail-closed loopback URL, and ambient `DATABASE_URL`, `PG*`, Docker auth/config, Python injection paths, tokens, and keys are not inherited. The local Python runtime that launched the controller is prepended to `PATH`, so bounded worker/reviewer checks reuse its installed project dependencies without installing or downloading anything. GitHub, Docker, PostgreSQL, npm, pip, cloud, and Kubernetes config paths are redirected to empty per-run locations while local saved login remains available to signed tools. Antigravity additionally receives a fresh per-run HOME/USERPROFILE and explicit safe settings, so permissive user-global settings are neither consumed nor modified; the OS keyring remains the only auth bridge. This is least exposure, not a hard security boundary: a worktree and a CLI sandbox are not equivalent to an isolated machine. Therefore only trusted backlog specs are dispatched, concurrency is at most two writers, and high-risk changes require the owner.

Publishing an exact-SHA image after a trusted `main` gate remains artifact delivery. Production and staging deployment stay BLOCKED until their separately documented owner inputs exist.
